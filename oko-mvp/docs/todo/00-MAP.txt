THE VISION (docs/adr/0003)
--------------------------
ỌKỌ is a place, not an application:
  - the terminal can MAKE a UI, not just print to one;
  - HTML applications work directly with the computer (host API + capability
    policy behind them);
  - games can run against server-side Vulkan;
  - minimal, hot-swappable, extremely flexible on machines that have nothing;
  - the interface is a real Star Trek computer, not a terminal in LCARS colours.

The load-bearing decision: ỌKỌ renders web content ITSELF. A page is rendered by
the host's Servo, headless, never by whatever browser is displaying the shell.
The host streams frames; the shell is a view that draws pixels and sends input.
Same view in a browser, in a Servo window, on a DRM framebuffer, or over a
network — the transport changes, the view does not.

HOW TO RUN AND CHECK THINGS
---------------------------
  build:                   cargo build --offline --jobs 2
  the gate:               make check          (budget + typecheck + clippy + tests)
  the console:            systemctl --user restart oko-web
                          curl -sS -o /dev/null -w '%{http_code}\n' \
                            http://127.0.0.1:8099/apps/computer.html
  ask the host directly:  TOKEN=$(curl -sS http://127.0.0.1:8099/ | \
                            sed -n 's/.*oko-token" content="\([a-f0-9]*\)".*/\1/p')
                          curl -sS -X POST http://127.0.0.1:8099/api \
                            -H "X-Oko-Token: $TOKEN" \
                            -d '{"v":1,"id":"1","direction":"request",\
                                 "route":"host.browser.engine","payload":{}}'
  render a page headlessly, no display server needed:
                          third_party/engines/servo/servoshell -z -o out.png \
                            --screen-size=1280x800 <url>

HOUSE RULES THAT BIT US ALREADY (AGENTS.md)
-------------------------------------------
  - test first; paste the RED, then the GREEN. A test that passes immediately
    was not testing the new behaviour.
  - 200 lines per file, tests included. Name the seam, never shuffle code.
  - a split that moves a test module MUST declare `#[cfg(test)] mod tests;`.
    This was forgotten twice, once by a subagent and once by me, and it silently
    disabled 4 tests and then 6.
  - verify the COMMIT, not the working tree: check it out in a worktree and run
    the gate. Three commits on master do not build in isolation because of this.
  - do not trust a subagent's summary, or its silence. Three of three failed
    here: a broken tree with disabled tests, a package of todo!() stubs, and
    twenty minutes that produced no files. Verify by running the gate.
